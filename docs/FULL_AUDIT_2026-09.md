# Full audit — 5 September 2026

**Question asked.** Is every part of the project working, from the editor down
to a system a web site can actually integrate — and does the standalone demo
show the default face?

**Scope.** `main` at PR #88: the unit suite, the production build, every
Playwright suite the repository defines, the export pipeline, the exported
runtime loaded standalone, the runtime demo, and the documentation that
describes them. Environment: Node 22.22, Vite 6.4.3, Playwright 1.55 with the
container's Chromium 1194 (the version Playwright pins was not installed, so it
was pointed at the one present; nothing in the repository changed for that).

The rest of this document is what was run, what it said, and what was fixed.
**Fixed** landed in this pass with tests; **Kept** was examined and left;
**Not run here** could not be exercised in this container and is covered by CI.

## 2. The chain a web site depends on

Read as one path, from authoring to a page:

1. **Template → project.** `applyTemplateProject` rigs the parsed artwork:
   18 authored parameters (46 with the per-side offsets the face control rig
   adds), 3 states with guarded transitions, 6 clips, 4 behaviours, 8 shape
   keys, 7 pins, a 139-cell 2.5D turn, the gaze solver and 5 followers.
   `templates.test.js` validates it; every id it names is drawn.
2. **Project → export.** `createExportRig` writes schema version 4 with every
   additive block; `bundleRuntimeSource` joins the 20 runtime modules into one
   file and refuses a name collision. `export-lifecycle`, `runtime-api` and
   the release regressions cover it.
3. **Export → page.** `load({ mount, svg, rig })` fetches or takes the values,
   mounts, binds click and hover, starts. The public methods are the ones the
   README and `docs/RUNTIME_API.md` list; `setParameter` refuses unknown
   names, `setState` refuses a transition the rig does not declare, and
   nothing uses `eval` or `new Function`.
4. **Page → pixels.** With `lookX` at 0.8 the left pupil is translated 6.4
   units; `happy` brings `smile` to 1 over the authored 350 ms; `head-nod`
   plays and reports itself. Measured in Chromium on the demo, and in Node on
   the bundled runtime with a fake document (`demo-assets.test.js`).

The link that was missing was the last one being *shown*: see F1.

## 3. Findings

| # | Finding | Evidence | Resolution |
|---|---|---|---|
| F1 | **The runtime demo did not show the mascot.** `/demo/` drew a blue disc with one black eye and drove it with a two-parameter rig written inline in `demo.js`, importing the runtime *source* rather than the file Export ships. The README called it "the same engine shipped by Export"; the engine was, the mascot, the rig and the integration were not. | `project/editor/demo/index.html`, `demo.js` (old) | **Fixed.** The demo loads the Mascot Face from `mascot.svg`, `rig.json` and `runtime.js` next to the page, exactly as a site would, and exposes every state, motion, parameter and behaviour through the public API, printing each call. Playwright covers it on Chromium (critical), Firefox and WebKit (smoke) and on the deployed Pages URL. |
| F2 | **No way to obtain the template's export without a browser**, so the demo's files would have had to be generated by hand and checked in, and would have drifted. | `template-loader.js` parses on the canvas only | **Fixed.** `template-export.js` builds the template project from its own markup (a parser for that markup alone; user SVG keeps the sanitized DOM import) and `scripts/demo-assets.mjs` writes the three files. Vite emits them at build time and serves them in `npm run dev`; `npm run demo:assets` writes them to a folder. The Node output was compared byte for byte with the editor's download of the same template: identical `rig.json`, identical `runtime.js`. |
| F3 | **A dead fixture.** `project/demo/index.html` embedded a `mascot.svg` that no build ever produced, outside the Vite root, referenced by nothing. | `project/demo/` | **Fixed.** Removed. |
| F4 | **The README said rig schema 3; the code writes 4.** `RIG_MODEL.md` was titled "schema version 4" and said in its body that Export "always writes `schemaVersion: 2`". | `README.md` §Export, `docs/RIG_MODEL.md` | **Fixed.** Both say 4, and that 1 to 3 are read and upgraded — which `normalizeRig` does. |
| F5 | **The runtime size in the docs was a fifth of the real one.** 46.7 kB / 16.2 kB gzip in two places; the file is 216.8 kB / 62.8 kB, the editor 1.16 MB / 353 kB. | `docs/RUNTIME_API.md`, `docs/RUNTIME_PERFORMANCE.md` | **Fixed.** Tables updated, with why: the face control rig, and the file being shipped unminified and commented. |
| F6 | The exported `mascot.svg` and the template's markup differ in serialization only (ids on the clip-path children, `/>` spacing); the picture is the same. | export in Chromium vs `face-artwork.js` | **Kept.** The demo serves the template's markup; the test asserts every rigged id is drawn in it. |
| F7 | The editor chunk exceeds Vite's 500 kB warning. | build output | **Kept.** Known (`docs/RUNTIME_PERFORMANCE.md`); the editor is one page, the runtime a site loads is separate and 63 kB compressed. |
| F8 | A rig's size is almost all its keyform grid (139 cells for the head turn), 257 kB indented, 9.3 kB compressed. | `dist/demo/rig.json` | **Kept.** Served compressed by every static host; noted in the performance doc. |
| F9 | The per-side offsets (`lookXLeft`, `smileRight`, …) are parameters like any other, with nothing in the rig to say they are secondary. | `rig.params` | **Kept.** The demo folds them by name under *One side at a time*; a flag on the parameter record would be an additive schema change and is not needed for a page to work. |

## 4. Verdict

Everything the repository defines as a gate passes, on the code as found and on
the code as changed. The chain from the template to a page is exercised at
every joint by a test, and the demo is now the proof a visitor can see: the
default face, loaded from the three exported files, driven by the public API.
What this pass could not do is run Firefox and WebKit, which CI does on each
push; the demo's own smoke test is in that job.
